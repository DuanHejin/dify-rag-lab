# Chat Assistant Prompt Experiments

> 用途：记录 Dify Chat Assistant 阶段的提示词版本、实验目标、测试输入和效果观察。

## 应用信息

- 应用类型：Chat Assistant
- 应用名称：简单的求职聊天助手
- 模型：`doubao-seed-2-0-lite-260428`
- 当前阶段：阶段 1，控制台单轮和多轮对话已验证
- 记录日期：2026-05-21

## Prompt V1

### System Prompt

```text
你是一个求职准备助手，请根据用户输入，用中文给出清晰、可执行的建议。
```

### 设计意图

- 先验证 Dify Chat Assistant 的最小可用提示词。
- 让助手聚焦求职准备场景。
- 要求输出中文，避免中英文混杂。
- 强调“清晰、可执行”，便于后续评估回答质量。

### 已验证内容

- 控制台调试与预览可以正常输出。
- 单轮对话可以正常回答。
- 多轮对话可以承接上下文继续回答。

### 待补充测试样例

```text
我准备面试前端开发岗位，只有 3 天时间，应该怎么准备？
```

```text
我简历里项目经验比较少，怎么在面试中表达自己的能力？
```

```text
面试官问我为什么离职，我应该怎么回答？
```

### 后续优化方向

- 增加回答结构，例如“目标、步骤、注意事项、可直接使用的话术”。
- 增加追问策略，当用户信息不足时先提问，而不是直接泛泛建议。
- 增加岗位、年限、面试轮次、剩余准备时间等变量意识。
- 增加边界约束，避免编造公司、岗位或用户经历。

## Prompt V2 发布机制实验

### 临时修改

```text
每次回答开头都输出【求职助手V2】。
```

### 实验结果

- 不发布，直接用 API 调用：返回中没有 `【求职助手V2】`。
- 点击发布更新后，再次用 API 调用：返回中出现 `【求职助手V2】`。

### 结论

- 调试预览可验证草稿配置。
- API 调用使用已发布配置。
- 修改提示词后，必须发布更新，外部 API 才会按新提示词运行。
